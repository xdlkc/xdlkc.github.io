# Spec: TOC 滚动时同步 URL 锚点（replaceState）

日期：2026-03-12 14:38 (Asia/Shanghai)

Slug: toc-hash-sync

## 背景/问题
当前文章页的 TOC 高亮能随滚动更新，但浏览器地址栏的 `#hash` 只在点击 TOC 时才会变化。

这导致：
- 读到中间某一节时，直接复制地址栏链接分享，落点仍然是页面顶部或旧锚点
- 刷新页面后无法回到“当前阅读到的章节”

## 目标（用户可感知）
当用户在文章页滚动阅读时，地址栏的 hash 会自动变为当前激活章节的 `#<heading-id>`（不新增历史记录、不跳动页面）。

## 需求
1) 在 TocScrollSpy 计算出 active heading id 后：
   - 若当前 `location.hash !== #${activeId}`，则使用 `history.replaceState(null, '', '#${activeId}')` 同步。
   - 必须使用 **replaceState**（不污染 back/forward 历史）。
2) 不改变现有行为：
   - 点击 TOC 仍然 `pushState`（保持可回退）。
   - deep link（带 hash 打开）仍然要做 header offset 的 scroll 修正。
3) 边界/保护：
   - activeId 为空时不更新。
   - 若页面当前 hash 指向的不是文章 heading（例如其它组件锚点），不强制改写（仅在 activeId 属于 headings 时同步）。

## 验收标准
- 滚动到不同章节时，`location.hash` 会变为对应 `#id`，且不会新增 history 条目（通过 replaceState）。
- 自动同步 hash 不应触发页面滚动跳动。
- 测试用例覆盖：滚动触发 scroll handler 后，replaceState 被调用且 hash 更新为目标 heading。

## 不做什么
- 不做“记住上次阅读位置”跨会话恢复（另一个 feature）。
- 不新增 UI 元素/按钮，仅增强锚点导航体验。
