# Spec: 文章页 TOC 自动生成（缺失时兜底）

- 时间：2026-03-07 18:34 (Asia/Shanghai)
- Slug: auto-toc

## 背景 / 需求
当前主题的 `toc-scrollspy.js` 依赖页面里已经存在由模板生成的 TOC（`.toc-nav a[href^="#"]`）。当某些页面/文章未生成 TOC（例如模板条件、手写页面、渲染异常或未来迁移到不生成 TOC 的布局）时，右侧 TOC 区域会空白，锚点导航与滚动高亮功能也随之失效。

## 目标
当页面存在 `.toc-nav` 容器但内部没有任何 TOC 链接时：
1) 自动从正文（`.article-content`）的 `h2/h3/h4` 生成 TOC 列表并注入到 `.toc-nav`。
2) 生成的 TOC 结构尽量复用现有 CSS（`toc-nav-level-*` / `toc-nav-link`）。
3) 生成后继续沿用现有的 smooth scroll + scrollspy 高亮逻辑。

## 验收标准（可测试）
- 给定一个包含 `.toc-nav`（空）与 `.article-content`（含 h2/h3） 的 HTML：调用 `initTocScrollSpy()` 后，`.toc-nav` 内应出现与 heading 数量一致的 `a[href^="#"]`。
- 自动生成的链接文本应等于对应 heading 的 `textContent`（trim 后）。
- 若 heading 原本没有 `id`，调用后应被自动补齐且 `href` 指向该 id。
- 若 `.toc-nav` 已有链接，则不应重建/覆盖（保持现有行为）。

## 边界 / 非目标
- 不做多层级嵌套缩进的完美树形结构（只需生成基本列表；缩进由 CSS class 体现）。
- 不处理 `h1`（通常为标题），默认从 `h2` 起。
- 不改动 Hexo 的 TOC helper 输出（仅在 TOC 缺失时兜底）。

## 实现草案
- 在 `themes/evan/source/js/toc-scrollspy.js` 中新增 `buildTocIntoContainer(toc, headingElements)`：
  - 若 `.toc-nav` 内没有 `a[href^="#"]`，创建 `<ol>`，为每个 heading 创建 `<li class="toc-nav-level-${level}">` 与 `<a class="toc-nav-link" href="#${id}">`。
  - level 取自 tagName（H2/H3/H4）。
- `initTocScrollSpy()` 在读取 `tocLinks` 前/后执行一次兜底生成，并重新获取 `tocLinks`。
