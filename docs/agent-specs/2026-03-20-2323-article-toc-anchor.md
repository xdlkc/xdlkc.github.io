# 文章页自动 TOC（目录）与锚点导航功能规范

## 需求 (Requirement)
在博客文章页面自动生成目录（Table of Contents, TOC）并为文章标题添加锚点导航功能，提升用户阅读体验和内容可发现性。

## 验收标准 (Acceptance Criteria)

### 1. 自动生成锚点
- **AC1.1**: 所有文章页面的 `<h2>` 和 `<h3>` 标题应自动生成唯一的 ID 属性，作为可直接访问的锚点链接。
- **AC1.2**: 生成的 ID 应具有语义化，例如基于标题文本，并确保全局唯一性（例如通过 slugify 处理）。
- **AC1.3**: 当用户点击生成的目录项时，页面应平滑滚动到对应的标题位置。

### 2. 目录显示与交互
- **AC2.1**: 页面侧边栏（如果可用）或文章内容区域附近应显示一个可点击的目录。
- **AC2.2**: 目录应动态列出所有 `<h2>` 和 `<h3>` 标题，并保持层级结构（例如 `<h2>` 为一级，`<h3>` 为二级）。
- **AC2.3**: 目录项应清晰可辨，并能通过 CSS 突出显示当前在视口内的标题对应的目录项。
- **AC2.4**: 在小屏幕设备（例如移动手机）上，目录应自动隐藏或以更紧凑、可折叠的方式展示，不影响主要内容阅读。

## 边界 (Boundaries)

- **只处理特定标题级别**: TOC 和锚点功能仅限于 `<h2>` 和 `<h3>` 标题。`<h1>`（通常是文章标题本身）和 `<h4>` 至 `<h6>` 标题不包含在目录中。
- **样式与集成**: TOC 的外观样式应与博客现有设计风格保持一致，不引入突兀的视觉元素。
- **页面范围**: 此功能主要针对 `_posts` 目录下的文章详情页。其他页面类型（如主页、归档页、标签页）不在此次功能范围内。
- **依赖**: 优先使用现有库或轻量级解决方案，避免引入大型框架。
