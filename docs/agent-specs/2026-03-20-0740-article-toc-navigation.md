# Spec: 文章页自动 TOC (目录) 与锚点导航

## 需求 (Requirement)

本功能旨在为博客文章页面提供自动生成的目录 (Table of Contents, TOC) 和锚点导航，提升用户阅读体验，方便快速定位文章内容。

1.  **自动生成目录:** 在文章详情页加载后，根据文章内容中的 H2 和 H3 标题自动生成目录。
2.  **可点击导航:** 目录应为可点击的链接，点击后页面平滑滚动到对应的标题位置。
3.  **实时高亮:** 页面滚动时，目录应实时高亮当前在视口（viewport）内的标题所对应的目录项。
4.  **标题锚点:** 文章中的 H2 和 H3 标题应自动添加唯一的 ID 作为锚点，支持直接通过 URL 链接到文章的特定部分。
5.  **空目录处理:** 如果文章中没有 H2 或 H3 标题，则不显示目录区域。

## 验收标准 (Acceptance Criteria)

1.  **目录生成:** 访问任意包含 H2/H3 标题的文章页面，页面上应出现一个结构化的目录区域。
2.  **内容匹配:** 目录中的每一项都应准确反映文章中的一个 H2 或 H3 标题，并保持其层级关系（H2 为一级，H3 为二级）。
3.  **平滑滚动:** 点击目录中的任一链接，页面应平滑滚动到相应的标题位置，而不是瞬间跳转。
4.  **高亮显示:** 滚动文章内容时，当前可见区域的 H2 或 H3 标题在目录中对应的项应被高亮显示，以指示用户当前阅读的位置。
5.  **URL锚点:** 滚动或点击目录项时，浏览器地址栏的 URL 应自动更新，包含当前标题的锚点（例如 `#/section-title`）。
6.  **无标题情况:** 访问一篇不包含任何 H2 或 H3 标题的文章页面，页面不应显示目录区域。
7.  **样式兼容:** 目录的视觉样式应与现有博客主题保持一致，不引入视觉上的破坏性变化。

## 边界 (Boundaries)

1.  **适用页面:** 本功能仅应用于识别为“文章详情页”的页面（例如，通常由 `_posts` 或 `source/_posts` 目录下的 Markdown 文件生成的页面）。
2.  **标题层级:** 仅处理 H2 和 H3 标题。H1 标题通常是文章主标题，不纳入目录。H4 及更低层级的标题不作为目录项。
3.  **技术栈:** 优先使用原生 JavaScript 或现有库（如 jQuery，如果项目已引入）实现，避免引入新的大型前端框架。CSS 样式应封装，避免全局污染。
4.  **性能:** 目录生成和高亮逻辑应尽可能高效，不应显著影响页面加载速度或滚动性能。
