# Spec: 文章页标题自动生成锚点 ID（修复 TOC/锚点导航）

- 时间：2026-03-11 00:20 (Asia/Shanghai)
- Feature slug: heading-auto-anchors

## 背景 / 问题
当前文章/页面的目录（TOC）与“复制本节链接”依赖标题元素存在稳定的 `id`。但在某些渲染情况下（不同 Markdown/HTML 来源、手写 HTML、部分插件输出），标题可能没有 `id`，导致：
- TOC 点击不跳转 / 滚动定位不准
- 标题旁的锚点复制按钮不出现或复制无效

## 目标
在前端运行时自动为 `.article-content` 内的标题（h1-h6）补齐稳定的 `id`，并在必要时同步 TOC 链接的 `href`，保证目录导航与锚点复制在“无标题 id”场景下也可用。

## 需求
1) 自动生成标题 `id`
- 当标题元素缺少 `id` 时，基于标题可见文本生成 slug，并写入 `id`。
- 遇到重复标题（生成相同 slug）时，后续标题自动追加 `-2`, `-3`… 保证唯一。
- 已有 `id` 的标题保持不变。

2) TOC 链接兜底修复
- 对页面内 `.toc-nav a[href^="#"]`：若其 `href` 指向的目标不存在，则尝试按“链接文本 == 标题文本（顺序匹配）”找到对应标题，并将 `href` 更新为该标题的 `#id`。

3) 运行范围
- 仅处理 `.article-content` 内标题。
- 不处理代码块/预格式化区域内部的“伪标题”。

## 验收标准
- 给定一段正文包含没有 `id` 的 `<h2>`，初始化后该标题拥有非空 `id`。
- 存在两个相同文本标题时，生成的 `id` 唯一且后者带数字后缀。
- TOC 中一个链接 `href="#xxx"` 但页面不存在 `id=xxx` 时，初始化后该链接 `href` 会被修复为实际标题 `id`。
- `npm test` 通过。

## 非目标 / 边界
- 不做复杂的多语言分词/拼音转换；slug 规则保持简单、可预测即可。
- 不重排 TOC 层级结构；仅做“目标锚点缺失”的修复。
- 不影响已有正确工作的页面（已有 id / TOC 正常时应保持行为稳定）。
