# Spec: 文章页自动 TOC（目录）与锚点导航

## 背景
文章正文已经存在标题结构，但文章页需要稳定提供：

- 自动目录（TOC）渲染
- 标题锚点可跳转
- 桌面端与移动端都可访问
- 标题缺失 `id` 时仍能工作

该功能属于文章页 P0 导航能力，要求在常规技术文章中默认可用。

## 目标
- 在文章页检测到正文标题时自动展示目录。
- 目录项链接到对应标题锚点。
- 点击目录项后按固定头部偏移滚动，避免标题被遮挡。
- 正文标题缺失 `id` 时，前端自动补齐且保证唯一。

## 非目标
- 本次不设计新的视觉风格改版。
- 本次不实现目录拖拽、搜索、虚拟化等增强能力。
- 本次不处理非文章页的额外 TOC 自定义配置。

## 用户故事
- 作为读者，我打开一篇长文时，希望看到自动生成的目录，快速定位章节。
- 作为读者，我点击目录项时，希望页面滚动到正确标题位置，而不是被顶部导航遮住。
- 作为维护者，我希望即使 Markdown 标题没有显式锚点，目录导航仍然稳定可用。

## 功能要求
1. 文章模板在存在标题时输出 TOC 容器，至少包含：
   - 移动端 `details.toc-mobile`
   - 桌面端 `aside.toc-card`
2. TOC 内容来自文章正文标题，支持 `h2/h3/h4` 层级。
3. 若标题没有 `id`，系统自动生成 slug，并对重复标题追加 `-2`、`-3` 后缀。
4. 若 TOC 容器为空，前端可根据正文标题自动补建目录结构。
5. 点击 TOC 链接后：
   - 更新 hash
   - 按头部高度 + margin 偏移滚动
   - 移动端自动关闭目录抽屉
6. 标题数量不足 2 个时，桌面端 TOC 可自动隐藏，减少噪音。

## 验收标准
1. `themes/evan/layout/post.ejs` 中存在文章页 TOC 生成逻辑，并同时输出移动端和桌面端容器。
2. `themes/evan/source/js/toc-scrollspy.js` 能为缺失 `id` 的标题补齐锚点。
3. 空 TOC 容器在初始化后可自动生成可点击目录链接。
4. 目录层级能反映 `h2/h3/h4` 嵌套关系。
5. 相关单元测试通过。

## 测试策略
- 模板测试：验证文章页模板接入 TOC 容器与脚本初始化。
- 单元测试：验证标题 `id` 补齐、TOC 自动生成、层级嵌套和锚点 href。
- 行为测试：验证点击目录项的偏移滚动和移动端自动关闭。

## 实现说明
- 复用现有文章页模板与 `toc-scrollspy.js`，避免引入第二套 TOC 运行时。
- 以增量方式暴露 TOC 构建逻辑，便于独立单测和后续扩展。
