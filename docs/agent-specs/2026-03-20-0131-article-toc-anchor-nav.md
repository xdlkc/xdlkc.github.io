### 需求 (Requirement)
在博客文章页面，自动生成一个侧边栏目录（Table of Contents），展示文章中的所有标题（H1-H6）。目录项应可点击，点击后平滑滚动到对应的文章区域。当用户滚动页面时，目录中的当前可视区域标题项应高亮显示。

### 验收标准 (Acceptance Criteria)
1.  **自动生成:** 文章加载时，根据文章内容中的 `<h1>` 到 `<h6>` 标签自动生成目录。
2.  **可点击导航:** 目录中的每个标题项都是一个链接，点击后页面平滑滚动到对应的标题位置。
3.  **锚点链接:** 每个标题在 DOM 中应具有唯一的 ID，目录项链接到这些 ID。
4.  **实时高亮:** 当用户滚动页面时，根据当前在视口中的标题，目录中对应的项应高亮显示。
5.  **嵌套层级:** 目录应反映标题的层级结构（例如，H2 嵌套在 H1 下）。
6.  **用户感知:** 目录应在文章页面的侧边栏或易于访问的位置显示。

### 边界 (Boundaries)
1.  **技术栈:** 基于当前项目所使用的技术栈实现（例如，如果使用 Hexo/Jekyll/Next.js，则利用其模板或插件机制）。
2.  **样式:** 初始实现无需复杂样式，以功能实现为主，高亮效果简洁明了。
3.  **性能:** 生成目录和滚动监听的性能开销应尽可能小，不影响页面加载和滚动流畅性。
4.  **内容:** 只处理 Markdown 渲染后的 HTML 中的标题标签，不修改原始 Markdown 文件。
5.  **空文章:** 如果文章没有标题，则不显示目录。
6.  **移动端:** 初始阶段不强制要求移动端适配，但应考虑其可扩展性。
