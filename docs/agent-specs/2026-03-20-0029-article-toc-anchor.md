# Feature Specification: 文章页自动 TOC（目录）与锚点导航

**Date:** 2026-03-20
**Feature Name:** 文章页自动 TOC（目录）与锚点导航 (Automatic TOC and anchor navigation for article pages)
**Priority:** P0

## 需求 (Requirements)

为博客文章页面自动生成目录（Table of Contents, TOC），并为文章中的标题（H1, H2, H3）添加锚点导航功能。用户能够通过点击目录项快速跳转到文章的不同章节，并通过 URL 锚点直接分享特定章节。

## 验收标准 (Acceptance Criteria)

1.  **TOC 可见性:** 在所有博客文章页面（posts）中，如果文章包含 H1, H2, H3 标题，则自动生成并显示一个 TOC 侧边栏或顶部导航。
2.  **TOC 内容:** TOC 应准确列出文章中的 H1, H2, H3 标题，并保持其层级结构（例如，H2嵌套在H1下）。
3.  **导航功能:** 点击 TOC 中的任意条目，页面应平滑滚动到对应的标题位置。
4.  **URL 更新:** 点击 TOC 项或直接滚动到某个标题时，浏览器的 URL 应自动更新为包含对应锚点哈希（#）的形式。
5.  **锚点图标:** 标题（H1, H2, H3）旁边应显示一个用户友好的锚点图标（例如，一个链接符号或 # 符号），当鼠标悬停在标题上时可见，或者始终可见。点击图标可复制带锚点的链接。
6.  **无标题处理:** 如果文章不包含任何 H1, H2, H3 标题，则不显示 TOC。
7.  **样式一致性:** TOC 的样式应与博客现有主题风格保持一致。

## 边界 (Boundary Conditions)

1.  **标题级别:** 仅处理文章内容中的 H1, H2, H3 标签作为 TOC 的条目。
2.  **TOC 位置:** 初步实现为文章内容区域的左侧或右侧固定区域，或在内容上方。
3.  **TOC 动态性:** 初始版本不要求 TOC 随滚动高亮当前章节，但后续可考虑作为优化。
4.  **长 TOC 处理:** 如果 TOC 过长，应支持滚动，但不强制实现折叠/展开功能。
5.  **冲突处理:** 确保自动生成的 ID 不与现有页面元素 ID 冲突。

## 技术实现初步考虑

*   遍历文章内容，提取 H1-H3 标签。
*   为每个标题生成唯一的 ID 作为锚点。
*   构建 TOC 列表，并插入到页面指定位置。
*   使用 JavaScript 实现平滑滚动和 URL 哈希更新。
*   考虑使用现有的主题或插件机制进行集成。
