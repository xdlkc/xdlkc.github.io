# 功能规格：文章页自动 TOC（目录）与锚点导航

## 需求 (Requirements)

1.  博客文章页面应自动生成文章目录（Table of Contents, TOC）。
2.  TOC 应包含文章内所有 `<h2>` 和 `<h3>` 标题。
3.  TOC 列表项应是可点击的链接，点击后页面应平滑滚动到对应的标题位置。
4.  文章内所有 `<h2>` 和 `<h3>` 标题应自动添加唯一的 `id` 属性作为锚点。
5.  当用户滚动页面时，TOC 中当前处于视口内的标题对应的列表项应高亮显示，以指示当前阅读位置。
6.  TOC 应具有良好的可访问性（Accessibility）和响应式设计（Responsive Design）。

## 验收标准 (Acceptance Criteria)

1.  **TOC 生成与显示:** 访问任意一篇包含多级标题（H2, H3）的文章页面，在侧边栏或指定区域能看到自动生成的TOC。
2.  **链接与滚动:** 点击TOC中的任意链接，页面能够平滑滚动到对应的文章标题。
3.  **锚点存在:** 检查文章DOM，所有 `<h2>` 和 `<h3>` 标题元素都包含一个唯一的 `id` 属性。
4.  **高亮显示:** 滚动文章内容时，TOC中当前视口内的标题对应的列表项会动态更新高亮样式。
5.  **无标题情况:** 如果文章不包含任何 `<h2>` 或 `<h3>` 标题，TOC区域应自动隐藏或显示“无目录”等友好提示。
6.  **响应式表现:** 在不同屏幕尺寸（如桌面、平板、手机）下，TOC的布局和功能均正常，不会导致页面错乱。

## 边界 (Boundary Conditions)

1.  **标题层级:** TOC仅处理 `<h2>` 和 `<h3>` 标签。更高或更低层级的标题不包含在内。
2.  **ID 生成:** 锚点 `id` 的生成规则应基于标题文本进行 `slugify` 处理，并确保在同一文档内的唯一性。例如，“Introduction to AI” → `introduction-to-ai`。
3.  **性能:** TOC的生成和更新机制应尽可能高效，不应显著影响页面加载或滚动性能。
4.  **实现方式:** 优先考虑在构建时（SSG）或首次渲染时生成DOM，然后通过JavaScript在客户端实现滚动监听和高亮逻辑。
