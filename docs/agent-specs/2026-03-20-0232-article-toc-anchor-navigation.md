# Feature Specification: 文章页自动 TOC（目录）与锚点导航

## 需求 (Requirements)
为博客文章页面自动生成目录（Table of Contents, TOC），并为文章内的标题（H1-H6）添加锚点导航功能。

1.  **自动生成 TOC:**
    *   在文章页面的特定位置（例如侧边栏或文章顶部）显示一个可折叠/展开的目录。
    *   目录内容应根据文章中的标题（H1-H6）自动提取和生成。
    *   目录应反映标题的层级结构。
2.  **锚点导航:**
    *   目录中的每个条目都应是可点击的链接，点击后平滑滚动到文章中对应的标题位置。
    *   文章中的每个标题（H1-H6）在渲染时应自动获得一个唯一的 ID，并显示一个锚点链接图标（如 # 或 🔗），点击该图标可将当前章节的 URL 复制到剪贴板，或直接跳转。

## 验收标准 (Acceptance Criteria)
1.  **TOC 可见性与准确性:**
    *   打开一篇包含至少两个标题（H1-H6）的博客文章，TOC 必须可见。
    *   TOC 的内容与文章中实际的标题文本、顺序和层级结构完全一致。
    *   如果文章没有标题或标题数量少于可配置的阈值（例如 2 个），则 TOC 不显示。
2.  **TOC 导航功能:**
    *   点击 TOC 中的任一链接，页面应平滑滚动至对应的文章标题位置。
    *   当页面滚动时，TOC 中对应的当前阅读章节应有高亮或选中状态。
3.  **锚点链接功能:**
    *   鼠标悬停在文章中的任何标题（H1-H6）上时，应显示一个可点击的锚点图标。
    *   点击锚点图标，浏览器 URL 应更新为包含该锚点 ID，并且可以复制该 URL 以分享特定章节。

## 边界与假设 (Boundaries and Assumptions)
*   **技术栈:** 假设博客基于 Hexo 或类似的静态站点生成器，HTML 渲染流程涉及 Markdown 到 HTML 的转换。
*   **实现位置:** TOC 的生成和锚点的插入可能需要修改主题模板文件、Hexo 渲染插件或自定义脚本。
*   **前端交互:** 初始实现可以采用基本的滚动和高亮，更高级的交互（如折叠/展开、滚动监听自动高亮）可在后续迭代中优化。
*   **CSS 样式:** 初始样式将是基础功能性的，美观性可在后续迭代中完善。
*   **Markdown 兼容性:** 确保与常见的 Markdown 标题语法兼容。
*   **ID 生成:** 标题 ID 需保证唯一性，并考虑处理重复标题文本的情况。
