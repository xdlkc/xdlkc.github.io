# Spec: Auto-hide TOC when article has too few headings

- Date: 2026-03-08 15:34 (Asia/Shanghai)
- Slug: toc-auto-hide

## Motivation / User value
Some posts are short (only one section heading). Showing the full TOC box in these cases adds visual noise without navigation value. This change makes TOC smarter: it only appears when it is actually useful.

## Requirements
1. On article pages, if the content contains **fewer than 2 headings** (within the configured TOC heading selector), the TOC container should be hidden.
2. If there are **2 or more headings**, TOC behavior stays unchanged (auto-generate anchors, scrollspy, smooth scroll, etc.).
3. The TOC hiding should be done accessibly:
   - set `hidden` attribute on the TOC container
   - set `aria-hidden="true"` on the TOC container
4. Do **not** auto-hide the mobile TOC container when it is inside `<details class="toc-mobile">`.

## Acceptance Criteria
- Given a DOM with `.toc-nav` and `.article-content` containing only 1 heading, after `initTocScrollSpy()`:
  - `.toc-nav` has `hidden` attribute
  - `.toc-nav` has `aria-hidden="true"`
- Given 2 headings, `.toc-nav` is **not** hidden and scrollspy can still mark an active item.

## Non-goals / Boundaries
- Do not change TOC markup or styling beyond hiding the container.
- Do not change heading selection rules; only use the existing `headingSelector` behavior.
- Do not attempt to hide/expand any mobile TOC wrappers (e.g. `<details class="toc-mobile">`) in this iteration.

## Rollout / Risk
Low risk: only hides TOC when it would have at most one entry.
