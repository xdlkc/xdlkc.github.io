# Spec: 站内搜索弹窗（标题/标签高亮 + 无结果建议）

## 背景 / 目标
当前站点导航没有可用的站内搜索入口。希望提供一个轻量、无需后端的本地搜索弹窗：
- 读取站点根目录的 `db.json`（已存在）
- 支持按 **标题 + 标签** 搜索
- 命中结果中对关键词做 **高亮**
- 无结果时给出 **可操作的建议**（例如去 Archives、缩短关键词）

这是一个“小而完整、用户可感知”的功能：用户在任意页面点击「搜索」即可快速定位文章。

## 需求
1. 所有主要页面（首页、文章页、归档页、普通 page）导航栏增加「搜索」按钮。
2. 点击「搜索」打开弹窗（overlay / dialog 均可）：
   - 包含输入框、关闭按钮、结果列表区域。
   - 打开后输入框自动聚焦；Esc 或关闭按钮可关闭。
3. 输入关键词后展示结果：
   - 至少搜索：title、tags（如果存在）。
   - 结果按简单相关性排序：title 命中优先于 tag 命中；命中次数多者靠前。
   - 展示：标题（带高亮）、可选的标签（带高亮）、链接。
4. 高亮规则：
   - 对用户输入做 HTML escape 后再渲染。
   - 匹配采用不区分大小写的子串匹配；用 `<mark>` 包裹。
5. 无结果建议：
   - 明确提示“无结果”。
   - 提供至少 2 条建议，其中一条是可点击跳转到 `/archives/`。
6. 性能/边界：
   - `db.json` 仅首次打开弹窗时 fetch 一次并缓存。
   - 关键词为空或仅空白时不展示结果。
   - 如果 `db.json` fetch 失败，提示失败并建议去 Archives。

## 验收标准
- 在模板中能看到「搜索」按钮，点击后出现弹窗。
- 输入一个存在于某篇文章标题的词，结果出现且标题中对应片段被 `<mark>` 高亮。
- 输入一个不存在的词，出现“无结果”与建议（含 Archives 链接）。
- `npm test` 通过。

## 非目标
- 不做全文内容索引（仅 title/tags）。
- 不引入第三方大型搜索库。
- 不做拼音/分词/模糊匹配。
