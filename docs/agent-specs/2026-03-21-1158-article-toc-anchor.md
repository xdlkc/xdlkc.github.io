# Feature Specification: 文章页自动 TOC（目录）与锚点导航 [SDD+TDD]

## 需求 (Requirements)

在博客文章页面，根据文章的标题（H2, H3等）自动生成一个目录 (TOC)，并实现锚点导航功能。

-   **自动生成 TOC:** 根据文章内容中的 `<h2>` 和 `<h3>` 标签自动提取标题，并生成可点击的目录。
-   **锚点导航:** 点击目录中的任意项时，页面应平滑滚动到对应的文章标题位置。
-   **标题锚点:** 自动为文章中的 `<h2>` 和 `<h3>` 标签添加唯一的 ID 作为锚点。
-   **用户感知:** 目录应在文章内容旁边或顶部显示，便于用户快速浏览和跳转。

## 验收标准 (Acceptance Criteria)

-   **AC1: TOC 生成:** 当文章包含 `<h2>` 或 `<h3>` 标题时，页面上应在指定位置（例如，侧边栏或文章顶部附近）显示一个包含这些标题的 TOC。
-   **AC2: 链接正确性:** TOC 中的每个链接都应准确指向文章中对应的标题锚点。
-   **AC3: 平滑滚动:** 点击 TOC 链接后，页面应使用平滑滚动效果跳转到目标标题。
-   **AC4: 标题 ID:** 文章中所有 `<h2>` 和 `<h3>` 标签都应自动获得一个唯一的、可用于锚点导航的 ID。
-   **AC5: 空白处理:** 如果文章不包含 `<h2>` 或 `<h3>` 标题，则不应显示 TOC。
-   **AC6: 特殊字符支持:** TOC 和锚点能够正确处理包含中文、特殊符号等字符的标题。

## 边界 (Boundary Conditions)

-   **标题层级:** 本次迭代仅处理 `<h2>` 和 `<h3>` 标签作为 TOC 生成的依据。更深层级的标题（如 `<h4>`）暂不考虑。
-   **样式与位置:** TOC 的具体样式和在页面上的精确定位（例如，固定侧边栏、可折叠等）将在后续迭代中优化。本次重点在于核心功能实现。
-   **动态内容:** 暂不考虑文章内容通过 JavaScript 动态加载或渲染的情况。假定文章内容在页面加载时已存在于 DOM 中。
-   **性能:** 对 TOC 生成的性能影响应最小化，避免对页面加载速度造成显著影响。
