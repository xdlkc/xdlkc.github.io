嗨，欢迎收听本期的技术精读。今天咱们来聊《构建智能体：何时将子智能体并入主智能体循环》。先说一个熟悉又让人抓狂的场景：你搭了个客服智能体，结果十几个专家各管一摊，路由半天，回复还慢。

很多团队会本能地觉得，任务复杂就该上多智能体。可文章的反直觉结论是：不少路由器、规划器和领域专家重新并回主循环后，质量反而更高，成本和延迟也更低。关键不是智能体越多越强，而是上下文有没有浪费在一次次交接上。

子智能体本来有价值。它有独立上下文、专属工具和指令，适合并行研究、独立验证和模块化权限。文章讨论的不是全部消灭，而是随着模型变强，哪些边界已没必要存在。

你可能见过一套典型五层流水线：请求先过意图分类器，再进固定五步推理，按用户分群落到推荐分支，最后由多智能体编排器拼答案。听起来很工程化，实际像机场转机五次，每个闸口都可能把行李信息弄丢。

文章推荐的架构简单得多：一份清晰系统提示词，四到五个轻量数据工具，明确输出护栏，再加一个开放式主循环。模型需要哪项能力就加载什么，像随身带份目录，用到哪页再翻哪页。

这背后最关键的，是共享上下文。一个智能体亲手做完查询、分析和修正，能看到每一步为什么这么做，而不是只收到专家交回的摘要。信息不再经过有损交接，最终答案自然更容易保持一致。

渐进式披露也不只是省钱。技能按需加载团队流程，工具搜索按需暴露工具；模型起初只看简介，需要时才读完整说明。再叠加更强的模型能力，很多外部编排步骤都能交回模型，Claude Code 的系统提示词甚至精简了八成以上。

那什么时候该保留子智能体？三个信号很实在：主循环上下文已膨胀到可量化地变差；多个任务必须用独立新上下文并行，做完就丢；或者工具太多、指令冲突，单智能体已经选不明白。碰到这些硬约束，别硬合并。

这里有个值得记住的判断：按上下文拆，还是按问题类型拆。写功能、写测试、再审查，像按工种切三个人，信息每传一次就磨损一次。让同一智能体掌握完整背景，再派黑盒验证器跑测试，边界反而清楚。

大型组织尤其容易把组织图画成智能体图。每个团队做一个专家，中央平台再搭编排器，最后几百个重叠子智能体挤在一起。代码能跑，组织也看得懂，但谁对最终体验负责，反而没人说得清。

接着就是拼凑式提示词：销售、物流、客服各加一句，规则打架，品牌语气失控。评测也被切碎，每个团队只测自己的一小块，没人维护从用户请求到最终答案的全局成绩单。这就是康威定律在智能体设计里的翻版。

复杂度还会直接吃掉延迟。文章提到，有客户把多智能体框架换成单智能体循环后，速度大约快了两倍。用户多等一秒，团队多烧一点钱，品牌还多掉一点信任；架构图上的每一层，最后都会变成用户面对的沉默。

那是不是把所有东西都塞进主智能体？不是。中央团队应统一守住系统提示词和端到端质量，每个新技能、新工具、新评测上线前都把关。领域能力由各团队贡献，但中央团队要小，否则审批链又会长成另一座多智能体城市。

目标单循环怎么跑？模型每轮发出一批工具调用，框架并行执行，把原始结果送回同一模型；再由它决定继续调用、追问，还是回答。计划和执行也由同一模型完成，收到结果便改计划，规程进技能，审批和检索进工具。

迁移别靠感觉。先建端到端评测集，十个黄金样本也能起步，中央团队看最终任务完成度，各业务团队为自己的技能附小评测。保留编排器时看路由是否选对，并入之后，就看技能和工具是否被正确触发。

然后一次只动一个子智能体。共享上下文的专家可以合并；需要独立能力的，先包装成工具；真正要并入的，就把原提示词变成技能，把 API 调用变成工具。比较并入前后，不只看总分，更要看哪些具体任务发生翻转。

文章举了个扎心例子。物流专家并入后，延迟确实降了，可主智能体手里有订单工具，就自己回答送达日期，不再询问物流专家。它不是不会答，而是漏掉了流程；平均分可能还行，关键链路却悄悄断了。

所以评测要覆盖生产里的协同调用链，也要覆盖绝不能违反的规则，而且每个任务多跑几次。另一个安全垫是先把子智能体当工具调用，让主智能体继续掌控对话；这能快速建立基线，但摘要损耗和嵌套循环仍会保留。

工具和技能怎么放？实时数据、固定动作和权限检查适合做成工具，并按用户意图分组；工具定义超过三四十个，模型选择能力往往下降。团队流程和判断标准放进技能，政策、指标与规格放进可检索知识库，别再全量粘进提示词。

迁移工具包还提供 build eval、prompt audit、hillclimb 和 cost optimize，分别帮你搭评测、清理旧模型遗留规则、迭代优化描述、拆解成本。背后原则很朴素：量化评测，每次只改一个变量，留下经得住检验的方案。

所以，子智能体不是坏架构，失控的交接才是。可以先把专家从“同事”改成“技能加工具”，让主智能体持续理解用户目标；只有遇到上下文膨胀、独立并行或复杂冲突时，才保留真正的多智能体边界。少一次交接，就多一份完整；少一层架构，往往就快一点。
