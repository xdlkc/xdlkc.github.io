嗨，欢迎收听本期的技术精读。今天咱们来聊《从 AGENTS.md 到确定性护栏》。先说个熟悉的场景：Agent 十分钟改完一个功能，你打开 Diff，密密麻麻全是补丁，Review 审到下班都审不完。

更扎心的是，功能虽然合进去了，下一周却冒出一堆怪问题。于是大家都养成了同一个习惯：往 AGENTS.md 里再补十条规则。文件越来越厚，模型该犯的错却一点没少。

这次来自 AI Engineer Code Summit 的分享者是 Lauren Tan。她参与过 React Compiler 重写，也在 Cursor 做过研发，如今负责 xAI Grok Bot 工程团队；半年重构环境后，吞吐、稳定性和客户端性能一起变好。

她的判断是，当语法生产成本趋近于零，工程师的元工作不再是亲手把需求翻译成代码，也不再是堆更长的 Prompt，而是改造代码库和工具链，让概率性的 Agent 默认只能写出合规代码。

那 AGENTS.md 为什么越写越厚、约束力却越来越弱？条目一多，注意力就被稀释，局部经验还会被当成全局教条；适用范围又说不清。最致命的是，它没有编译期阻断力，构建流程不会因为一段严厉的 Markdown 报错退出。

Lauren 的解法延续自编译器背景：Hook 用错时，编译器会在编译期直接拦下，而不是发一篇最佳实践长文。她把信任模型画成 Poteto Pyramid，从 API、静态分析、自动化验证、自然语言规则，一直排到人类审查。

所以铁律是：每纠正一次 Agent 的错误，先别加提示词，试着把约束往上抬。让 API 根本写不出坏用法，让 Linter 毫秒级拦下，让测试产出证据，实在没办法才交给人眼看。

这里有个反直觉点：对编码 Agent 来说，仓库比 Prompt 更重要。Prompt 只是任务引子，模型检索进来的现有代码才占上下文大头；一段临时补丁留在主干，下一个 Agent 会把它当示范，再复制到五个新模块。

Grok Bot 自研了内部框架 Dune，像给 Agent 铺好带围栏的跑道。最狠的一刀，是业务代码彻底禁用 React 的 useEffect，只允许框架底层少数受控封装调用，闭包、竞态和级联重渲染这一整类问题就此消失。

另一个例子，是用目录本身做上下文。主进程和渲染进程分别放进 electron-main 和 electron-renderer，再配静态依赖分析；渲染进程要守住高帧率，跨目录偷跑的重 I/O，会在第一秒被弹回。

接下来这条最反直觉：Grok Bot 禁掉了百分之九十九的代码注释。原因是注释没有执行力、容易腐烂，而 Agent 很擅长用一段漂亮解释，给自己的临时方案办理免责声明。

她在 Cursor 遇到过命令式工作台和 React 界面异步错位，Agent 修不动根因，就用定时器把报错往后推几毫秒。屏幕不报错了，V8 堆内存却被短命定时器撑大，主垃圾回收一跑，应用就周期性卡顿。

更妙的是，Agent 每塞一个定时器，还会配一段论证自己为何“不得不这么做”的长注释。这其实是模型的逃生舱：既要消除报错，又要显得专业。于是 Dune 干脆不给它辩解机会，把正确修法写进教学型 Lint 报错里。

但静态检查只能证明代码守规矩，证明不了业务算得对、并发不丢消息。Grok Bot 每天约三百个 PR、单月上万个，人逐行看 Diff 根本做不到，还会掉进自行车棚效应：改动越大，越只挑无关痛痒的问题。

于是评审对象变了，人主要看机器生成的验证产物，而不是原始 Diff。属性随机测试、UI 模糊测试、TLA+ 建模和 Lean 证明一起上；过去写规约太贵，现在模型能帮忙写，七成 Token 投给验证，这笔账第一次算得过来。

但别急着照抄七成这个数字。头部实验室 Token 充裕，普通团队未必划算；更务实的是先把零 Token 的目录边界、框架原语和带修复建议的 Lint 做到极致，再把昂贵测试集中砸到支付、权限和状态同步上。

还有个数学约束：外循环必须晚于内循环。单次生成干净 PR 的概率如果是八成，有人盯着还能兜底；十次无人干预连续叠加，健康概率只剩大约百分之十。自动化不会创造秩序，只会放大你原来的工程底色。

等内循环被架构边界、教学型 Lint 和四层验证硬化，外循环才安全。比如发布客户端新版本时，云端 Agent 会像真实用户一样做全量模糊测试，发现问题自动提修复 PR，跑完门禁再合入。

指标和节奏上都得留心眼：PR 数量受拆分粒度影响，回滚率也不等于线上逃逸缺陷率；更要命的是，核心界面改得太勤会打乱用户预期，所以新功能仍要先内部试用，哪怕 Agent 几分钟就能做完。

这套思路也和 Harness Engineering 汇流了。生成器与评估器拆开、确定规则与模型决策分层，核心都是更厚的外围护栏。

所以最值得带走的，是工程师从语法手艺人变成不变量立法者，让经验沉淀在仓库里，持续校准未来的并发 Agent。下次看到临时补丁和长篇辩解，先别加规则，想想能否用十行确定性检查，让整类错误物理绝迹。
