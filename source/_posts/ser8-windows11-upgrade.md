一台 Ryzen 7 8845HS、32GB 内存的小主机，升级 Windows 11，按理说不该为硬件发愁。可我的零刻 SER8 就停在了兼容性检查这一步：系统认不出 TPM。

我最在意的还有另一件事：电脑里的文件和已经装好的软件，能不能一起留下来？重新装系统容易，把工作环境一点点搭回去才麻烦。

这篇记录的是我在 2026 年 9 月 30 日的一次实际升级。从检查电脑、更新 BIOS，到找到真正起作用的设置，再到确认 Windows 11 已经装好，中间也走了几段弯路。

![这次升级的实际过程：检查 TPM、更新 BIOS、切换 ASP fTPM、重新检测、确认升级结果。示意图，不是系统截图。](/uploads/ser8-windows11-upgrade/upgrade-route.svg)

先把结果放在前面：**最终升级到 Windows 11 专业版 25H2，系统已激活。升级后抽查的工作目录和常用软件程序都还在。**这不等于我已经逐项测试了所有软件，但最担心的“整套环境被清空”没有出现在这些检查中。

真正让 TPM 检测恢复正常的，是下面这个选择：

**Trusted Platform Module：从 `Auto` 改成 `Enable ASP fTPM`。**

注意，这个结论来自我这台 SER8 的实际操作。下面会把机器和 BIOS 版本写清楚，方便对照，不建议拿着菜单名字去给其他电脑盲改。

## 配置明明够，为什么还不让升级？

我的机器是零刻 SER8，AMD Ryzen 7 8845HS，32GB 内存，1TB 固态硬盘。原来的系统是 Windows 10 专业版，简体中文、64 位。开始排查时，C 盘还有约 74GB 空闲空间。

检查下来，处理器、内存、磁盘容量都不是眼前的阻碍。系统盘已经使用 GPT，电脑也已经按 UEFI 方式启动，不需要为了升级再折腾分区。

问题集中在 TPM。

如果不熟悉这个词，可以先把它理解成电脑用来保管密钥、提供安全能力的一块“小保险箱”。Windows 11 要求 TPM 2.0。对我这次升级来说，关键是让 Windows 能正常认出并使用它。

当时的情况有点矛盾：BIOS 里写着“发现 TPM 2.0”，安全设备支持也已经打开；设备管理器里同样能看到 TPM 设备，可 Windows 的 TPM 查询却说没有找到可用的 TPM。

**看见设备名称、BIOS 显示已开启、Windows 真正能使用，是三件需要分别确认的事。**这也是这次排查最重要的一课。

## 先查清楚，再决定要不要动 BIOS

这次我让 Codex 帮忙查系统状态、找官方资料、整理结果，需要重启和进入 BIOS 的地方由我来操作。

过程中也出现过错误方向。我们一度怀疑系统缺少某个 TPM 服务，后来发现，单凭服务列表里没有那一项，不能判断系统坏了。这条判断被撤回，也没有去手工补服务。

系统文件检查确实发现并修复了一些损坏，但 TPM 的问题并没有因此消失。不能把“工具报告修复成功”直接理解成“这次升级的问题已经解决”。

接着查到零刻官方论坛的一条同型号经历：有人把 TPM 来源切到 ASP fTPM 后，Windows 10 终于能识别，升级检测也过了。

我照着找，却没找到那个菜单。

后来才注意到一个细节：**帖子里的 BIOS 是 15.13，我当时的是 15.08。**同一款机器，不同固件版本，菜单也可能不一样。网上一句“进入某某选项”，落到自己电脑上未必找得到。

## 更新 BIOS，是我这次走过的一步

我原来的 BIOS 是 `V029.P8C0M0C15.08`，日期为 2024 年 10 月 23 日。零刻官网有适用于 SER8 8745HS／8845HS 的新版，我这次更新到 `V035.P8C0M0C15.16`，日期为 2026 年 6 月 3 日。

这里要讲清楚：官方对这个版本的说明，主要是修复 Windows／AMD 驱动兼容性问题，**并没有承诺它能直接解决我的 TPM 问题。更新完 BIOS，Windows 当时仍然没有认出 TPM。**

所以，这不是一篇“遇到问题先刷 BIOS”的教程。如果你的机器已经有相应设置，应先核对当前状态；确实需要更新时，再从厂商官网确认适用型号、版本和操作说明。

实际准备更新盘时，我先确认了 U 盘的型号、容量和盘符，再将它格式化为 FAT32，按官方教程命名为 WINPE，把固件文件放到正确位置并校验。我的这份更新包从 U 盘启动后会自动调用刷写脚本，因此“选择 U 盘启动”就已经是在开始更新，不能把它当作随便试一下。

有两个很现实的小问题值得记下来：

- **格式化会清空的是所选 U 盘。**正常更新 BIOS 不会像重装系统那样清空 C、D 盘，但重要文件仍应先备份，刷写期间也要保持供电。
- 我把键盘接在显示器上时，开机按 F7 没有反应。遇到这种情况，可以先把键盘和更新 U 盘直接接到主机，再按厂商说明进入启动菜单。

进入 BIOS 后，这台电脑上的聊天自然就用不了了。后来我换了一个配合方式：把机器信息和已做过的操作整理好，在另一台电脑上继续和 agent 对照 BIOS 照片。这样不用一边猜菜单，一边反复退出重启。

## 真正起作用的设置：让 Windows 换一个 TPM 来源

更新后，我在本机 BIOS 里确认到了这条路径：

```text
Advanced
  → AMD CBS
    → SOC Miscellaneous Control
      → Trusted Platform Module
```

这里的可选项包括 Auto、Disabled、Enable dTPM、Enable ASP fTPM、Enable Pluton fTPM。

我最终只改了一个相关选项：

| 设置 | 原来的值 | 最后使用的值 |
| --- | --- | --- |
| Trusted Platform Module | Auto | **Enable ASP fTPM** |
| Pluton Security Processor | Auto | 保持 Auto |
| Security Device Support | Enable | 保持 Enable |

![本次实际设置：TPM 来源由 Auto 改为 Enable ASP fTPM，另外两个选项保持原值。此图是说明用示意图，不是 BIOS 截图。](/uploads/ser8-windows11-upgrade/tpm-choice.svg)

我没有修改 Device Select，没有清除 TPM，也没有恢复全部 BIOS 默认设置。切换前还查过磁盘加密：当时 C、D 盘都是完全解密，BitLocker 保护关闭。如果你的电脑开启了设备加密或 BitLocker，先确认恢复密钥已经妥善保存，再评估 TPM 相关修改。

保存并重启后，Windows 的检测结果终于变了：

- 找到了 TPM，主版本是 **2.0**。
- 厂商显示 **AMD**，固件版本为 **6.22.0.7**。
- TPM 已启用、已初始化，而且已经就绪。

读者不需要背这些数字。对普通用户来说，可以打开 `tpm.msc`，看它是否显示 TPM 已准备好使用，以及规范版本是否为 2.0。

这里还有一个容易误读的数字：检测结果中同时出现了 `1.59`，那是规范的修订号，不能据此说它是“TPM 1.x”。本机检测到的 TPM 主版本明确是 2.0。

至于原因，结合 BIOS 原来显示的 MSFT 厂商、Windows 10 的识别情况和切换后的结果，TPM 来源及兼容性是这次问题的重点。但我并没有因此推导出“所有 Pluton 都有问题”，也没有把论坛里“必须关闭 Pluton”的做法完整照搬过来。**在我的机器上，Pluton Security Processor 保持 Auto，同样解决了问题。**

## TPM 好了，升级提示却还可能停在过去

解决硬件识别后，还不能只盯着原来那条“不符合要求”的提示。

Windows 的兼容性检测有缓存。我的旧结果仍写着 TPM 不通过，时间却早于这次修复。我们重新运行了微软的兼容性评估任务，并核对结果的时间，才看到新的记录变成通过，阻止原因也清空了。

这一步可以理解成：已经把问题修好了，还要让系统重新“验一次货”。微软也提供了电脑健康状况检查工具，以及手动刷新兼容性评估的方法，文末放了官方说明。

当时还有两个细节没有被藏起来：

一是 **Secure Boot 支持，但没有开启**。微软对这条升级条件的表述是具备安全启动能力，不能把“没开启”直接等同于“不支持”。我这次没有为此继续修改 BIOS，新的兼容性评估也通过了。这不代表关闭安全启动更好，只说明它当时不是升级被拦住的原因。

二是 TPM 查询里仍有一个待重启标志，虽然设备已经就绪，兼容性评估也通过了。它被单独记了下来，作为安装前复核事项，没有据此继续清除 TPM 或反复改 BIOS。

## 我最关心的：怎么把文件和软件一起留下来？

到了这一步，才轮到 Windows 安装本身。

如果目标是原地升级、保留已经装好的软件，要抓住两个动作：**从现有 Windows 里启动安装程序；在最终确认页看清楚“保留个人文件和应用”。**

官方 ISO 可以直接从微软下载页面获取，也可以通过媒体创建工具保存。对我这套系统，需要匹配简体中文、x64，并包含专业版。下载后还可以按官网提供的 SHA-256 校验值检查文件是否完整。

用 ISO 升级时，在当前 Windows 中挂载它，再运行里面的 `setup.exe`。不要把之前“从 U 盘启动刷 BIOS”的经验，直接套到这一步：从安装 U 盘启动，是另一条安装路径，不能当作保留原有应用的原地升级方式。

如果安装界面只能选择“仅保留个人文件”，软件不会一起保留。遇到这种情况应先停下来，核对介质语言、版本和启动方式，别为了往下走就接受一个不符合自己目标的选项。

安装向导的每一屏，我没有完整记录下来，所以这部分分享的是保留环境必须核对的做法。**最终装成了什么、有没有激活，则是在升级后重新检查的。**

## 最后检查一遍，才算真的结束

升级后，这台 SER8 的实际系统是 **Windows 11 专业版 25H2**，内部版本为 **26200.9457**，已经激活。TPM 2.0 持续正常，安装流程也已经结束，Windows Update 和系统维护没有显示待重启。

我们还抽查了原来的工作目录和几款常用软件程序，确认它们仍然存在。日常功能是否全部正常，还要在接下来的使用中继续确认，不能因为文件夹在就替所有软件打包票。

C 盘空闲空间从升级前约 74GB 降到了约 32GB，旧系统目录 `Windows.old` 也还在。我暂时没有清理它，先确认常用软件和工作环境没问题，再考虑回收这部分空间。它可能用于系统回退，但不能当作长期备份。

这次折腾完，我最想留给同样遇到问题的人三句话：

**先看真实检测结果，别只凭一条旧提示判断电脑不行。**

**找 BIOS 设置时，型号和版本要一起对照。**

**要保留软件，就把“保留个人文件和应用”当成不能妥协的检查点。**

AI 在这次过程中确实帮我省了不少查资料、跑检查和整理记录的时间，也给过需要纠正的判断。最好用的配合方式，是让它每一步都拿出依据：当前是什么状态，改了什么，改完有没有重新验证。升级成功靠的正是这一轮轮核对。
